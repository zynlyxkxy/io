## 1 概述 <a id="ch1"></a>

### 1.1 设计目标 <a id="sec-1.1"></a>

封装统一的接口，让主控层无感任何底层信息的情况下，控制plc或acs的变量读写，命令下发，buffer调用。不用知道这个变量在 ACS 运动控制器上还是在 PLC 上，也不需要清楚具体如何获取。同时还要做到对外部请求的安全校验，主动回馈命令接收情况，执行完成情况等。

## 2 需求分解 <a id="ch2"></a>

### 2.1 通用需求 <a id="sec-2.1"></a>

**说明**：通用需求与本工程具体业务无关，是模块运行所必需的基础能力。

#### REQ-G-01 配置驱动，换机型不改代码

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-G-01 |
| **需求名称** | 配置驱动，换机型不改代码 |
| **需求指标** | 变量清单、硬件地址、各类周期全部来自配置文件；新增或修改变量只改配置，不改代码、不重新编译；变量编号头文件由脚本从配置生成 |
| **需求描述** | ① 主配置 `config.json` 给出 ACS/PLC 的地址、端口和轮询周期<br>② `acs/io_config.json`、`plc/io_config.json` 定义全部可以操作的变量和命令，以及他们的详细配置参数。 |
| **需求背景** | 不同项目的硬件不同，底层接口不同。若机型的接口配置写死在代码里，每个项目都要开发自己的io驱动工程 |
| **验证方法** | T |
| **验证环境** | 实机 |
| **优先级** | P1 |

#### REQ-G-02 统一 ACS/PLC 的 IO 接口，让上层无感底层的一切

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-G-02 |
| **需求名称** | 统一 ACS/PLC 的 IO 接口，让上层无感底层的一切 |
| **需求指标** | 同一功能只有一套接口，接口清单里没有"ACS 版"和"PLC 版"之分；上层代码中判断"变量在 ACS 还是 PLC"的语句为 0 处；两种硬件共用同一套入参结构、返回结构和同一套错误码（0~4）；新增或更换底层硬件时，上层调用代码改动量为 0 |
| **需求描述** | ① 接口按功能分组（读、写、推送），不按硬件分组：读模拟量只有一个读接口，不管这个变量在 ACS 上还是在 PLC 上<br>② 上层只传变量编号，模块内部按编号选出硬件、调用对应的底层接口，不向上层暴露任何分支<br>③ 两种硬件的差别（ACS 走厂商库、PLC 走 HTTP）全部收在 AcsIoModule / PlcIoModule 内部<br>④ 返回结构统一：AI/AO 是"错误码 + 数值"，DI/DO/Buffer 是"错误码 + 开/关"，错误码含义两边一致<br>⑤ 硬件出问题也走统一错误码（读失败 2 / 写失败 3），上层不用分别应付两种硬件的报错 |
| **需求背景** | 按硬件分两套接口的话，上层每处调用都得先判断变量在哪一侧，数据结构、错误码也要理解两份，换项目换硬件就得改上层。统一成一套后，上层只认编号，底层换谁、换几家都跟它无关 |
| **验证方法** | A |
| **验证环境** | 实机 |
| **优先级** | P1 |

#### REQ-G-03 推送数据和采集数据解耦

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-G-03 |
| **需求名称** | 推送数据和采集数据解耦 |
| **需求指标** | 采集周期与推送周期各自独立配置，默认均为 500ms；推送路径不访问硬件，硬件访问只发生在采集周期和显式读写请求里；两个周期互不等待，调整任一周期不影响另一周期；顶层数据按推送周期稳定刷新，不受某次采集快慢影响 |
| **需求描述** | ① 采集周期与推送周期各自独立计时，互不同步<br>② 采集周期：周期性地读取 PLC 和 ACS 的相关数据，写入内部缓存<br>③ 推送周期：周期性地把缓存里的数据推送给顶层，推送过程不访问硬件<br>④ 采集与推送通过中间的缓存完全解耦：采集完不会立刻推送，推送也不等采集结束<br>⑤ 效果：硬件按自己能承受的节奏取数，顶层按固定节奏拿到最新数据，顶层数据变化的周期十分规律，整体高效 |
| **需求背景** | 如果采完就推，推送节奏就被硬件速度绑架：某一轮硬件慢或超时，网络存在波动，推送跟着抖；上层想看得更快，只能把硬件也逼得更快，最后两边互相拖累。拆成两个周期、中间用缓存中转，采集按硬件扛得住的节奏走，推送按上层需要的节奏走，互不牵连——缓存就是这两条流水线之间的货架 |
| **验证方法** | T |
| **验证环境** | 实机 |
| **优先级** | P1 |

## 3 详细设计 <a id="ch3"></a>

### 3.1 架构设计 <a id="sec-3.1"></a>

#### 3.1.1 架构图 <a id="sec-3.1.1"></a>

```text
┌──────────────────────────── 调试界面 GUI（GUI_MDL_IO，Qt）────────────────────────────┐
│   MainWindow：连接服务、心跳看门狗、拉取变量目录                                        │
│   IoGroup：6 个页签（AI / DI / AO / DO / Setting / Buffer）                           │
│   小控件：AiWidget / DiWidget / AoWidget / DoWidget / SettingWidget / BufferWidget    │
└───────────────────────────────────────┬──────────────────────────────────────────────┘
                                        │  RPC（ZMQ）：查询目录、读写、订阅推送
                                        ▼
┌────────────────────────── IO 服务程序（CTL_MDL_IO，Qt）───────────────────────────────┐
│  IoServer ── 收发中转：把 RPC 请求转给控制层，把推送发回上层（纯转发，不做判断）          │
│                                            │                                         │
│                                            ▼                                         │
│  IoController ── 核心控制：按编号找变量、区分硬件、缓存、周期推送、写后校验、心跳          │
│                                            │                                         │
│                                            │                                         │
│                                            ▼                                         │
│  AcsIoModule ── ACS 侧读写与轮询          PlcIoModule ── PLC 侧读写与轮询              │
│      │                                        │                                      │
│  AcsClient（ACS 官方库封装）               PlcClient（HTTP + JSON）                    │
└──────┼────────────────────────────────────────┼──────────────────────────────────────┘
       ▼                                        ▼
   ACS 运动控制器（TCP）                      PLC（HTTP）
```

#### 3.1.2 架构元素 <a id="sec-3.1.2"></a>

| 架构元素 | 说明 |
|---------|------|
| IoServer | RPC 服务入口，继承平台生成的接口骨架。只做转发和打印入口日志，不含业务判断 |
| IoController | 模块的核心。负责编号解析与硬件选择、变量查表、读写调用、缓存、周期推送、写后校验、心跳 |
| ConfigManager | 单例。启动时加载主配置与两套变量配置，建立"编号 → 变量信息"的索引表，供控制层查询 |
| AcsIoModule | ACS 侧硬件访问层。登记需要轮询的 AI/DI/回读变量/Buffer，提供读写、Buffer 启停与状态查询 |
| AcsClient | ACS 官方库的封装。负责建立连接、变量读写、整数/实数转换、Buffer 操作 |
| PlcIoModule | PLC 侧硬件访问层。按机台部件路径登记回读变量，负责轮询、命令执行、参数设置 |
| PlcClient | PLC 通讯封装，通过 HTTP 收发 JSON，负责取回读值、执行命令 |
| GUI MainWindow | 调试界面主窗口：连接服务、心跳检测、发现变量目录、超时重连 |
| GUI IoGroup | 按目录动态生成 6 个页签，接收周期推送刷新控件，把用户操作转成 RPC 调用 |
| GUI 小控件 | 单个变量的显示与操作单元（数值框、状态点、开关按钮、启停按钮） |

#### 3.1.3 依赖关系 <a id="sec-3.1.3"></a>

本组件依赖以下外部能力：

| 依赖组件 | 依赖说明 |
|---------|---------|
| 平台 RPC 框架（中间件） | 提供 RPC 服务骨架、订阅推送和线程池；地址与超时来自 `mw_config.yaml` |
| ACS 官方库（SDK） | 提供 ACS 控制器访问能力，需随程序部署动态库与授权文件 |
| PLC 网络接口（HTTP/JSON） | PLC 侧需开启网络服务，被测命令、回读变量、参数项需在 PLC 工程中已定义 |

### 3.2 状态机 <a id="sec-3.2"></a>

**说明**：本组件对外没有明显的运行状态，唯一需要跟踪的内部状态是"某个变量的写后校验进行到哪一步"。状态集合即下表所有状态，初始状态为上电/启动即进入；对外呈现的状态通过"外部状态"列映射（即推送给上层的校验结果）。

**状态设计**

| 内部状态 | 外部状态 | 进入条件 | 退出条件 | 进入时执行 | 退出时执行 |
|---------|---------|---------|---------|-----------|-----------|
| 空闲 | 无推送 | 启动；或该变量的校验已结束 | 收到该变量 `verify=true` 的写请求 | / | / |
| 校验中 | 推送"校验通过 / 超时 / 下发失败" | 写入下发成功且 `verify=true` | 回读值与期望值一致；或超过 `verifyTimeoutMs` | 记录开始时间与期望值，放入校验队列 | 推送完成结果，移出队列 |

**状态迁移**：

| 当前状态 | 触发事件 | 目标状态 | 说明 |
|---------|---------|---------|------|
| 空闲 | 写请求 `verify=true`，下发成功 | 校验中 | 记录期望值，开始计时 |
| 空闲 | 写请求 `verify=true`，下发失败 | 空闲 | 立即推送"下发失败"，不入队 |
| 空闲 | 写请求 `verify=false` | 空闲 | 下发即结束，不推送 |
| 校验中 | 回读值与期望值一致 | 空闲 | 推送"校验通过" |
| 校验中 | 超过校验超时时间 | 空闲 | 推送"校验超时" |
| 校验中 | 同一变量再次写入 | 校验中（不变） | 拒绝本次写入，返回"忙" |

### 3.3 对外接口 <a id="sec-3.3"></a>

**说明**：接口定义见 `interface/include/io_controller.h` 与 `ioc_data.h`。所有接口的通讯层返回固定为成功，真正的业务结果放在返回数据的错误码字段中（0 表示成功，其他见 3.6.1）。

#### 3.3.1 通用接口 <a id="sec-3.3.1"></a>

**说明**：通用接口是与具体变量业务无关的公共通道，所有上层程序都会用到。

#### IF-G-01 心跳通知

| 字段 | 内容 |
|------|------|
| **接口编号** | IF-G-01 |
| **接口名称** | 心跳通知（IOHeartbeat） |
| **接口类型** | 订阅（服务端 → 客户端推送） |
| **接口声明** | `subscribe virtual ISTARResultStatus IOHeartbeat(OUT IoHeartbeatData &data) = 0;` |
| **前置条件** | 客户端已连接服务并注册该回调 |

### 3.4 数据定义 <a id="sec-3.4"></a>

#### 3.4.1 枚举定义 <a id="sec-3.4.1"></a>

**（1）变量号段划分**

号段由"变量编号 ÷ 1000"得出，决定变量类型和所属硬件。每个号段预留 1000 个编号。

| 号段 | 编号范围 | 所属硬件 | 变量类型 | 说明 |
|------|---------|---------|---------|------|
| 0 | 0~999 | PLC | AI | PLC 模拟量输入 |
| 1 | 1000~1999 | ACS | AI | ACS 模拟量输入 |
| 2 | 2000~2999 | PLC | DI | PLC bool量输入 |
| 3 | 3000~3999 | ACS | DI | ACS bool量输入 |
| 4 | 4000~4999 | PLC | AO | PLC 模拟量输出 |
| 5 | 5000~5999 | ACS | AO | ACS 模拟量输出 |
| 6 | 6000~6999 | PLC | DO | PLC bool量输出 |
| 7 | 7000~7999 | ACS | DO | ACS bool量输出 |
| 8 | 8000~8999 | PLC | Setting | 参数项，小数与开关共用该号段，具体类型由配置决定 |
| 9 | 9000~9999 | ACS | Buffer | 动作序列，配置中给出对应的 Buffer 号 |
| 10 | 10000~10999 | PLC | Cmd | 命令，配置中给出参数名列表 |

判定规则：号段为偶数归 PLC，奇数归 ACS；号段 8、9、10 属于固定用途，不再按奇偶判断。

### 3.5 配置文件 <a id="sec-3.5"></a>

#### 3.5.1 配置文件清单 <a id="sec-3.5.1"></a>

| 文件路径 | 格式 | 关键字段 | 读写时机 |
|----------|------|---------|---------|
| `<配置根>/io_config/config.json` | JSON | acs/plc 的 ip、port、pollPeriodMs、configPath；observerPeriodMs；verifyTimeoutMs | 服务启动时读取一次 |
| `<配置根>/io_config/acs/io_config.json` | JSON | AI / DI / AO / DO / Buffer 各数组，元素含 id、name（Buffer 还含 bufferId） | 服务启动时读取一次 |

### 3.6 错误码 <a id="sec-3.6"></a>

#### 3.6.1 错误码定义 <a id="sec-3.6.1"></a>

**（1）读写与操作接口返回码**

| 错误码 | 宏定义 | 错误描述 | 触发条件 | 处理建议 |
|--------|--------|---------|---------|---------|
| 0 | IO_SUCCESS | 成功 | 操作正常完成 | — |
| 1 | IO_ERR_NOT_FOUND | 编号不存在 | varId 不在配置中，或号段与操作类型不匹配 | 核对变量编号与配置文件 |
| 2 | IO_ERR_READ_FAILED | 读取失败 | 硬件通讯出错、无返回 | 检查 ACS/PLC 连接与地址配置 |
| 3 | IO_ERR_WRITE_FAILED | 写入失败 | 下发命令时硬件通讯出错或命令执行失败 | 检查硬件状态与被调用的命令是否存在 |
| 4 | IO_ERR_BUSY | 忙 | 同一 varId 上一次校验尚未结束 | 等收到校验完成通知后再写 |

**（2）校验完成码（推送）**

| 错误码 | 错误描述 | 触发条件 | 处理建议 |
|--------|---------|---------|---------|
| 0 | 校验通过 | 回读值与期望值一致（浮点容差 1e-12） | — |
| 1 | 校验超时 | 超过 `verifyTimeoutMs` 仍未一致 | 检查气路/机构是否卡滞、期望值是否给错 |
| 2 | 下发失败 | 写入命令本身失败，未进入校验 | 查写入失败原因后重新下发 |

## 4 交付件定义 <a id="ch4"></a>

| 交付件 | 描述 | 交付时机 | 验收标准 |
|-------|------|---------|---------|
| IO 服务程序（CTL_MDL_IO） | 服务端可执行程序，含 ACS 与 PLC 对接、配置加载、周期推送、写后校验 | 每次发版 | 能连接现场硬件，通过接口完成全部读写操作，日志完整 |
| 调试界面程序（GUI_MDL_IO） | Qt 调试工具，6 个页签展示并操作全部变量 | 每次发版 | 能自动发现变量、显示实时值、完成写入与启停操作 |
| 对接头文件（interface/include） | `io_controller.h`、`ioc_data.h`，以及生成的 rpc动态库 | 接口或变量变更时 | 上层仅依赖这三个文件即可完成对接 |
| 配置模板（config/） | `config.json`、`acs/io_config.json`、`plc/io_config.json`、`mw_config.yaml` | 每次发版 | 新机型按模板填变量与地址即可运行，无需改代码 |

### 优先级定义

| 优先级 | 说明 | 验收要求 |
|:------:|------|----------|

| **T** | 测试验证 — 通过执行测试用例验证功能和性能 |
